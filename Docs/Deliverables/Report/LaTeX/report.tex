\fmheading{Abstract}

Most video games ship with gigabytes of files made by artists: 3D models, photographs for surfaces, recorded sounds. \textit{Sentinel} takes the opposite route. It is a complete game engine and an open-world military shooter in which \emph{nothing} is loaded from a model, image or sound file. Every tree, building, soldier, vehicle, surface texture, cloud and sound effect is created while the program starts, from short mathematical recipes and a random seed. Only the small text files that hold the shader programs are read from disk.

The engine is written in the Odin language on OpenGL~4.1 (the newest version macOS offers, which has no compute shaders), and is organised in six layers, each allowed to depend only on the layers beneath it. A deferred renderer draws the scene in two steps: first it records what every pixel is made of, then it lights it with a sun and moon, spot and point lamps, cascaded shadow maps, screen-space ambient occlusion and reflections, an atmospheric sky with wind-driven clouds, fog, bloom, tone mapping, colour grading and anti-aliasing. Surfaces come from 18 texture recipes built on periodic gradient noise, domain warping and cellular noise; normal maps are derived from height fields with a Scharr filter. Objects and characters are tables of primitives with noise deformers. On top sit collision, a ladder state machine, four ground vehicles, a helicopter, enemy soldiers with stealth rules, synthesised audio and a five-objective rescue mission in the spirit of \emph{Project I.G.I.}

The project was measured and verified, not just drawn. At 1080p the renderer needs about 10.9~ms of GPU time per frame; 281 unit tests, 30 GL checks, 8\,318 texture checks (including exact tiling of every material), 318\,567 renderer checks and two scripted full playthroughs pass. The report explains each technique in plain language, supports it with the governing equations, and documents a debugging case in which a star in the fog colour painted a bright vertical line across the night scene.

\chapter{Introduction}

\section{Introduction}
Imagine a film studio where nothing is bought: not one prop, painting or costume. Instead, a recipe book tells assistants how to build every tree, wall and cloud while the audience waits, and the same recipe with a different ``seed'' number gives a different but equally believable forest. \textit{Sentinel} is that studio for a video game. It is a \emph{game engine} (the reusable machinery that draws, simulates and sounds a game world) together with a \emph{game} built on it: a first-person military mission in an open landscape. The word \emph{procedural} means ``made by a procedure'': geometry, colours and sounds are calculated by code instead of being stored.

\begin{plain}
A \textbf{GPU} is a second processor with thousands of tiny cores, built to colour millions of pixels at once. A \textbf{shader} is the small program every core runs for its pixel. A \textbf{texture} is a ``wallpaper'' stretched over a surface. Here, even the wallpapers are painted by shaders at start-up.
\end{plain}

\section{Background and Problem Statement}
Computer graphics teaches the pieces separately: transformations, lighting models, texture mapping, noise and image filtering. Real products need them to work \emph{together} at 60 frames per second. Normally the visible content is made in external art tools and loaded as large files, which hides how surfaces and shapes can come from mathematics. The problem addressed here is: \emph{can a complete, good-looking, playable 3D game be produced by code alone, within the limits of a student laptop?} Two limits make this hard. First, rules of the project: no model, image or precomputed data file is allowed. Second, the platform: macOS supports OpenGL up to version~4.1, which has no compute shaders and no shader storage buffers, so every filter and bake must be written as an ordinary full-screen pass.

\section{Objectives}
\begin{enumerate}[leftmargin=0.5in,label=\arabic*.,itemsep=0pt,topsep=0pt]
	\item Build a layered engine (platform, GPU, procedural content, world, renderer) with strict downward-only dependencies.
	\item Generate all meshes, textures and sounds at run time from code and seeds.
	\item Implement a modern real-time renderer: physically based shading, shadows, atmosphere, post-processing.
	\item Build a playable game on it: movement, weapons, enemies, vehicles, a helicopter, ladders, doors and a mission.
	\item Prove it works: unit tests, GL checks, scripted playthroughs and frame-time measurements within a 60 fps budget.
\end{enumerate}

\section{Unfamiliarity of the Problem and its Solution}
The design follows published theory but is not copied from a code base. \chapter{Related Works}

\section{Introduction}
Sentinel combines four research lines: procedural noise, physically based shading, real-time pipeline tricks and whole procedural games.

\section{Related Works}
\textbf{Noise.} Perlin's improved noise~[1] gives smooth random hills by blending random gradients on a grid; summing several scales (fractal Brownian motion) gives natural detail. Worley's cellular noise~[2] measures distance to random points and yields pebbles, leaves and cracks. Quilez's domain warping~[13] bends the sampling position by another noise to break grid-like patterns. Sentinel uses all three, made \emph{periodic} so textures tile without seams.

\textbf{Shading.} The Cook--Torrance microfacet model~[3] with the GGX distribution~[4] is the standard physically based reflection model; Karis~[5] showed a practical real-time form. Oren--Nayar~[8] models rough matte surfaces such as cloth.

\textbf{Pipeline.} Deferred shading~[14] separates ``what is visible'' from ``how it is lit''. Cascaded shadow maps~[7] give sharp nearby and coarse far shadows. Hillaire's sky model~[6] computes sunsets from scattering physics; ACES tone mapping~[9], FXAA~[11] and dithered output~[10] finish the picture.

\textbf{Whole games.} \textit{.kkrieger} (2004) squeezed a shooter into 96\,KB by generating content at run time. \textit{Project I.G.I.} (2000) inspired the mission design here: infiltrate a compound, hack, destroy, rescue, extract.

\section{Discussion}
Table~\ref{tab:compare} shows the gap. Existing teaching demos (such as step-by-step OpenGL tutorials) cover one technique each; commercial engines assume imported art; demo-scene shooters are not platform-independent teaching code. Sentinel adds a readable, layered, fully procedural engine with a complete game on macOS-limited OpenGL.

\section{Detailed Methodology}
\subsection{Problem Design and Analysis and Overall Framework}

\subsection{Procedural Geometry and Characters}
Every object is a \emph{table} of parts, each a primitive (box, sphere, cylinder, cone, capsule, torus, wedge), a transform, optional deformers and a material (Fig.~\ref{fig:parts}). A noise deformer pushes each vertex along its normal $\hat n$ by a smooth random amount, so a perfect sphere becomes a lumpy rock; with noise $\nu\in[-1,1]$ no vertex moves farther than the amplitude $A$:
\begin{equation}\mathbf p'=\mathbf p+A\,\nu(f\,\mathbf p)\,\hat n,\qquad \lVert\mathbf p'-\mathbf p\rVert\le A.\end{equation}
Taper, bend, twist and bulge are similar one-line deformers. Soldiers are a skeleton of capsules and boxes; a walk is a sine wave of phase, and a leg reaches its foot target by \emph{two-bone inverse kinematics}: for bone lengths $a,b$ and root--target distance $c$, the knee angle follows from the law of cosines,
\begin{equation}\cos\theta_{\text{knee}}=\frac{a^{2}+b^{2}-c^{2}}{2ab}.\end{equation}

\subsection{Procedural Textures}
Each material is a \emph{recipe}: a small shader that answers ``what is the colour, bumpiness, shininess and crevice-darkness at this point?'' The engine runs each recipe once at start-up into a 1024$\times$1024 picture (22 materials from 18 recipes, Table~\ref{tab:materials}) and keeps it on the GPU.

\begin{plain}
\emph{Gradient noise} is like a rubber sheet pinned at grid points, each pinned at a random slope: smooth, never repeating exactly. \emph{Fractal} noise adds finer and finer sheets on top, like hills, boulders and pebbles together.
\end{plain}

Gradient noise blends the four corner gradients $\mathbf g_c$ of the grid cell with the smooth curve $s(t)=6t^5-15t^4+10t^3$, scaled by $\sqrt2$ so that values lie in $[-1,1]$. Fractal noise sums octaves, each at double frequency and half strength:
\begin{equation}F(\mathbf x)=\frac{\sum_{i=0}^{n-1}2^{-i}\,\nu(2^{i}\mathbf x)}{\sum_{i=0}^{n-1}2^{-i}}.\end{equation}
Because corner gradients are chosen from the cell index \emph{modulo the period} $P$, $F(\mathbf x+P\mathbf e)=F(\mathbf x)$: the picture tiles with no seam (checked exactly by the test suite, Section~4.4). Variations give different materials: \emph{domain warping} $F(\mathbf x+s\,[F_1(\mathbf x),F_2(\mathbf x)])$ swirls the pattern (stone, wood, soil); \emph{ridged} noise $\sum a_i(1-|\nu_i|)^2$ makes cracks and bark; \emph{cellular} noise gives leaves and pebbles (Fig.~\ref{fig:noise}).

\begin{figure}[!tb]
	\centering
	\includegraphics[width=0.9\linewidth]{images/noise_stages.png}
	\caption{Noise ingredients (a re-implementation of the shader equations, for illustration): gradient, fractal, domain-warped, ridged, cellular.}\label{fig:noise}
\end{figure}

\textbf{Bumps without geometry.} A recipe also outputs a height map; the engine turns it into a \emph{normal map}, which fools the lighting into seeing bumps. The height slope uses the Scharr $3\times3$ filter, the most direction-fair small filter:
\begin{equation}\frac{\partial h}{\partial x}\approx\frac{3(h_{NE}+h_{SE}-h_{NW}-h_{SW})+10(h_E-h_W)}{32\,\Delta},\qquad \hat n=\frac{(-k\,h_x,\,-k\,h_y,\,1)}{\lVert\cdot\rVert}.\end{equation}
Where the height is below its neighbours' average (a crevice), albedo and ambient occlusion are darkened. On objects the picture is applied by \emph{triplanar mapping}: it is projected along the three axes and blended by $w_i=|n_i|^k/\sum_j|n_j|^k$, so deformed shapes never stretch the texture.

\subsection{The Rendering Pipeline}
\begin{plain}
\emph{Deferred shading} is like photographing a ``data poster'' of the scene first (every pixel's colour, direction and shininess), then lighting the poster once instead of lighting every object separately. It makes many lights cheap.
\end{plain}
The poster is the \emph{G-buffer} (Table~\ref{tab:gbuffer}). Figure~\ref{fig:pipeline} lists the passes. Direct light uses the Cook--Torrance model~[3]: a diffuse part plus a mirror-like specular part,
\begin{equation}f_s=\frac{D\,F\,G}{4(\mathbf n\!\cdot\!\mathbf l)(\mathbf n\!\cdot\!\mathbf v)},\quad D=\frac{\alpha^{2}}{\pi\big((\mathbf n\!\cdot\!\mathbf h)^{2}(\alpha^{2}-1)+1\big)^{2}},\quad F=F_0+(1-F_0)(1-\mathbf v\!\cdot\!\mathbf h)^{5},\end{equation}
where $D$ says how many tiny mirror facets face the viewer (GGX), $G$ how much they shadow each other, $F$ how much light reflects at a glancing angle (Schlick), and $\alpha$ is the surface roughness squared. Six illumination models are selectable per pixel (Lambert, Phong, Blinn--Phong, Oren--Nayar, Cook--Torrance, subsurface). Distant things fade into haze: with distance $d$ and density $k=3.5\times10^{-4}\,\mathrm{m^{-1}}$,
\begin{equation}C=T\,C_{\text{surface}}+(1-T)\,C_{\text{haze}},\qquad T=e^{-kd}.\end{equation}
Finally the HDR image is compressed to screen range with the ACES curve~[9] (Narkowicz fit), graded, dithered~[10] and smoothed (FXAA~[11]):
\begin{equation}C_{\text{out}}=\operatorname{clamp}\!\Big(\frac{x(2.51x+0.03)}{x(2.43x+0.59)+0.14}\Big),\quad x=\text{exposure}\times\text{radiance}.\end{equation}

\subsection{Sky, Time of Day and Clouds}
The sun's direction comes from astronomy: with latitude $\varphi$, declination $\delta$ and hour angle $h=15^{\circ}(\text{hours}-12)$, its height is
\begin{equation}\sin(\text{elevation})=\sin\varphi\sin\delta+\cos\varphi\cos\delta\cos h.\end{equation}
The colour of the sky is precomputed each frame into a small table from Rayleigh and Mie scattering (blue sky, red sunset)~[6]; the moon and a hashed star field take over at night. Clouds live on two imaginary planes, cumulus at $H=1500$\,m and thin cirrus at 7\,km. A view ray with direction $\mathbf d$ meets the plane at
\begin{equation}\mathbf P_{xz}=\frac{H}{d_y}\,(d_x,d_z)+\mathbf w\,t,\end{equation}
where $\mathbf w$ is the wind velocity: shifting the noise by $\mathbf wt$ makes clouds drift, and a faster-moving detail layer lets their shapes slowly change. The cloud colour is the sky's own grey, plus a sun rim by day and a moon rim at night.

\subsection{World, Physics and Gameplay}
\textbf{Terrain.} Ground height is fractal noise, warped and blended with a rounded ridged term, flattened into a plateau for the base: $h=h_0+A\,\nu(x,z)\,\operatorname{smoothstep}(r_0,r_0{+}w,\lVert\mathbf p-\mathbf c\rVert)$. It is meshed in 64\,m chunks that stream around the player; layers (grass, dirt, rock, sand) blend by slope and height with wandering borders.

\textbf{Trees.} Four species (oak, pine, birch, cypress) are each a few tables of limbs and leaf lumps. Every instance gets its own height, width, lean and tint, and the vertex shader bends it as a cantilever, $\Delta_{xz}\propto(0.04+0.1g)\,(y/9)^2$, where $g=\tfrac12+\tfrac12\sin(1.3t+0.05x+0.03z)$ is a travelling gust, plus a small leaf flutter.

\textbf{Collision and vehicles.} Solids are boxes that may be rotated, so walls are exact at any angle; the player is a capsule. Cars use the bicycle model, $\dot\psi=v\tan\delta/L$ (turn rate from speed, steering angle and wheel base $L$), and engine power fades toward top speed so acceleration is strong from rest and eases off:
\begin{equation}\dot v=a_0\Big(1-0.6\frac{|v|}{v_{\max}}\Big).\end{equation}
Four ground vehicles and a helicopter are boarded with E; the helicopter has a rotor spin-up and arcade flight model.

\textbf{Ladders} are a four-state machine (Fig.~\ref{fig:ladder}); while gripping, the controller, not the collision solver, owns the body, which removes getting stuck. Hands grip rungs hand over hand.

\textbf{Mission, AI and sound.} A staged objective machine drives five goals: enter the compound, hack the HQ computer, destroy the radar, rescue the hostage, reach the beacon. Soldiers patrol, see, hear (crouching is quieter), raise an alarm and call reinforcements; cameras sweep. All sounds (shots, steps, engines, alarm) are synthesised by oscillators and filtered noise shaped by envelopes and mixed in code. Progress is saved as plain text.

\section{Conclusion}
Each technique is small and data-driven; together they give a complete, deterministic world from seeds.

None is used. All content comes from fixed seeds, so every run is reproducible and no image, model or recording is stored.

\subsection{Analysis of the results}
Geometry is the largest cost because trees, base and terrain are drawn in detail, so instancing (one draw call for thousands of trees) and per-chunk culling matter most. Cheaper clouds (no warp in the sun-shading march, fewer octaves) kept the sky from growing the lighting pass. The bug in Fig.~\ref{fig:bug} was found by bisecting: remove draw items, lights and effects until the line disappeared, which pointed to the fog; it shows why every pass must have a test and a screenshot.

\chapter{Societal, Health, Environment, Safety, Ethical, Legal and Cultural Issues}

\section{Intellectual Property Considerations}
All code, shapes, textures and sounds are original; there are no third-party assets to license. Libraries (Odin, GLFW, miniaudio) are open source under permissive licences. The mission is inspired by, not copied from, \textit{Project I.G.I.}; no names, maps or art are reused.

\section{Ethical Considerations}
The game is a fiction about an invented compound with abstract, low-detail figures; it contains no real places, groups or people. It is intended for adult audiences. No personal data is collected: saves are local plain-text checkpoints.

\section{Safety Considerations}
Muzzle flash, alarm and explosions can bother light-sensitive players, and loud sound can hurt hearing, so brightness changes are smoothed, flashes are short and volume is mixed and limited. Playing sessions should include breaks.

\section{Legal Considerations}
Open-source licence terms are respected. Violence is stylised and the project makes no claim to real military accuracy. The report credits all cited work.

\section{Impact on Societal, Health and Cultural Issues}
Positive: an open, readable engine lowers the barrier to learning graphics. Negative: shooter games may encourage long play; a ``peaceful'' rescue and stealth emphasis (crouching, avoiding detection) is part of the design.

\section{Impact on the Environment and Sustainability}
Because no art files are downloaded, the whole project is a few megabytes of source, reducing storage and transfer energy. Frame-rate limiting through display synchronisation avoids needless GPU work.

\section{Complex Engineering Problems}
\textbf{Depth of knowledge:} radiometry, noise theory, numerical filters, GPU pipelines, collision and state machines. \textbf{Conflicting requirements:} realism versus a 16.7\,ms frame, no files versus rich surfaces, OpenGL~4.1 without compute shaders. \textbf{Depth of analysis:} bisecting the fog star streak, deriving tiling guarantees, tuning physics curves. \textbf{Interdependence:} renderer, world, game and audio share data layouts and timing.

% ============================================================
%  CHAPTER VII
% ============================================================
\chapter{Conclusions}

\section{Summary}
Sentinel shows that a complete 3D game, from surfaces and shapes to weather and sound, can be generated entirely by code under an OpenGL~4.1 limit. A six-layer engine, a deferred physically based renderer, noise-based material recipes, table-driven objects, a mission game with vehicles, ladders and stealth, and an extensive test suite fit in about 21\,000 lines and run within a 60 fps budget.

\section{Limitations}
Models are blocky (primitives plus noise); there is no true global illumination or ray tracing; foliage is lumpy volumes rather than individual leaves; the beacon is a solid column; guards cannot pick up dropped weapons; and the game was tuned by scripts and screenshots rather than a large playtest.

\section{Recommendations and Future Works}
Add leaf cards with cut-out transparency, screen-space global illumination, point-light shadows, anisotropic highlights, networked multiplayer, and a larger user study; port to a modern graphics API with compute shaders for GPU-side generation.
